# BookShelf

Android-приложение «книжная полка» для устройств с экраном на электронных чернилах (e-ink):
сканирует папки с книгами, разбирает метаданные и обложки, показывает библиотеку с фильтрами
по автору и серии, качает книги из OPDS-каталогов и открывает их во внешней читалке.
Основная читалка — **FBReader**. `minSdk 24` (Android 7.0), `targetSdk 35`.

**Сейчас в репозитории — каркас приложения:** 22 модуля, convention-плагины сборки, дизайн-система
под e-ink, абстракции всех слоёв, DI-граф, flavors, тестовая инфраструктура и CI.
Бизнес-логики ещё нет: каждая нереализованная часть помечена `STUB(Sprint N): …`
(см. [«Состояние»](#состояние-и-заглушки)).

## Быстрый старт

```bash
# Требуется JDK 17+ и Android SDK (compileSdk 35). Путь к SDK — в local.properties или ANDROID_HOME.
echo "sdk.dir=/path/to/Android/sdk" > local.properties

# Сборка и тесты
./gradlew :app:assembleFullDebug        # flavor full  (все файлы + CBR)
./gradlew :app:assembleFdroidDebug      # flavor fdroid (без CBR)
./gradlew :app:assemblePlayDebug        # flavor play  (SAF-only)
./gradlew testDebugUnitTest             # unit-тесты всех модулей (TDD-цикл)
./gradlew detekt                        # статический анализ
```

Установка на устройство:

```bash
./gradlew :app:installFullDebug
adb shell am start -n io.github.bookshelf.debug/io.github.bookshelf.MainActivity
```

Полезные скрипты (Node 20+, без зависимостей):

| Скрипт | Зачем |
|---|---|
| `node tools/check-versions.mjs` | Проверяет, что каждая версия из `gradle/libs.versions.toml` реально существует в репозитории, и печатает свежие стабильные версии |
| `bash tools/list-stubs.sh` | Печатает рабочий бэклог: все маркеры `STUB(Sprint N)` с файлами |
| `node tools/generate-launcher-icons.mjs` | Пересобирает PNG-иконки для API 24–25 |

## Структура модулей

```
:app                      Application, MainActivity, навигация, DI, воркеры, flavors
:core:common              AppResult/AppError, диспетчеры, логгер, часы, утилиты
:core:designsystem        e-ink тема, токены, компоненты, пагинация, обработка кнопок
:core:database            Room: сущности, DAO, FTS, конвертеры, миграции
:core:datastore           Настройки (DataStore), профили читалок (JSON)
:core:data                Доменные модели и репозитории — единственный фасад данных для UI
:core:storage             SAF: обход дерева, возобновляемый скан, потоки, хеши
:core:metadata            Парсеры форматов, кодировки, магия байт, извлечение обложек
:core:covers              Кэш обложек: диск (WebP), память (LRU), декодирование
:core:readerlink          Читалки: discovery, резолвер, запуск, адаптеры FBReader (L1/L2/L3)
:core:opds                OPDS 1.2: HTTP-клиент, парсер фидов, кэш, загрузки, авторизация
:core:eink                EinkController: Onyx, Rockchip-рефлексия, no-op, фронтлайт
:core:testing             Тестовые утилиты: правила, загрузчик фикстур, проверки AppResult
:feature:onboarding       Первый запуск: папки, читалки, объяснение ограничений SAF
:feature:library          Полка: сетка/список/компактный, пагинация страницами, кнопки
:feature:bookdetails      Карточка книги и действия с ней
:feature:collections      Коллекции и умные полки
:feature:search           Поиск по FTS с автодополнением
:feature:filters          Фасетные фильтры: автор, серия, жанр, формат, статус
:feature:catalogs         OPDS: каталоги, добавление вручную, браузер фида, загрузки
:feature:settings         Все настройки, включая e-ink и профили читалок
:feature:scan             Сканирование: прогресс, отчёт, дубликаты
```

**Правила зависимостей:** `feature:* → core:*` и никогда `feature:* → feature:*`;
`feature:*` не знает про `:core:database` (данные приходят через доменные модели `:core:data`);
публичный API модуля — только через интерфейсы, реализации скрыты.

Сборка настраивается не в 22 файлах, а в **convention-плагинах** (`build-logic/convention`):
`bookshelf.android.library`, `bookshelf.android.library.compose`, `bookshelf.android.feature`,
`bookshelf.android.hilt`, `bookshelf.android.room`, `bookshelf.android.application`,
`bookshelf.jvm.library`. Версии — только в `gradle/libs.versions.toml`.

## Разработка ведётся по TDD

Это обязательное требование процесса, а не пожелание — подробно в [`docs/tdd.md`](docs/tdd.md)
и ADR-012.

1. **Red.** Сначала тест, который падает по нужной причине.
2. **Green.** Минимальный код, делающий его зелёным.
3. **Refactor.** Приведение в порядок под защитой тестов.

Что из этого следует на практике:

* Парсеры форматов тестируются под Robolectric с **системным** `XmlPullParser` на API 24 —
  тест на JVM-реализации парсера не считается доказательством.
* Время, диспетчеры, каталоги и потоки приходят через интерфейсы (`AppClock`, `AppDispatchers`,
  `@CoverCacheDir`/`@TempDir`/`@ExportDir`, `SafTreeReader`, `BookInput`), поэтому логика
  тестируется без устройства.
* Для собственных интерфейсов пишутся фейки в `src/testFixtures` того модуля, которому интерфейс
  принадлежит; `mockk` — только для Android SDK, HTTP и AIDL.
* Фикстуры — в `<модуль>/src/test/resources/fixtures/<формат>/`, обязательные кейсы перечислены
  в `docs/tdd.md` §7.
* PR не проходит без теста на новое поведение, без теста миграции БД и при падении любого теста.

Стартовые «первые красные тесты» по модулям — в `docs/tdd.md` §8.

## Состояние и заглушки

Состояние проекта читается одной командой:

```bash
bash tools/list-stubs.sh          # или: grep -rn "STUB(" --include=*.kt .
```

Маркер `STUB(Sprint N): <что сделать>` — рабочий бэклог, привязанный к спринтам
[`docs/roadmap.md`](docs/roadmap.md). `TODO` без номера спринта в проекте не используется.
Часть найденных маркеров — исторические упоминания в комментариях («раньше здесь был `TODO`»),
поэтому число заглушек в отчёте инструмента больше числа реальных.

Планы и их статусы живут в хранилище планов, а `.dsh/plans/<slug>.md` — выгрузка из него
(её обновляет инструмент, руками такие файлы не правят). Старые планы в этом каталоге, написанные
до перехода на хранилище, остались историей: их отметки могут расходиться с кодом, и верить нужно
коду и текущей выгрузке.

**Что работает по-настоящему (и покрыто тестами).** На 01.10.2026 гейт — 1116 тестов, 0 падений,
detekt 0 замечаний, `:app:assembleFullDebug` собирается, четыре инструмента проекта
(`check-sources`, `check-versions`, `check-reachability`, `generate-structure --check`) проходят.

* **Данные**: Room, схема **версии 8** с миграциями 1→2…7→8 и FTS-поиском; DataStore-настройки;
  сканирование SAF курсором `DocumentsContract` с сохранением позиции, возобновлением и отметкой
  пропавших файлов; копии книг, заведённые читалкой, распознаются по содержимому (SHA-256).
* **Разбор**: метаданные читают десять разборщиков — FB2/FB2.ZIP (включая архивы), EPUB 2/3,
  PDF (`PdfRenderer`), TXT, CBZ (ZIP с `ComicInfo.xml`, обложка — первая страница в естественном
  порядке), CBR (тот же комикс, но RAR: правила разбора общие с CBZ, а чтение архива приходит
  портом и реализуется только во flavor `full` — `junrar` под UnRar License не проходит F-Droid),
  DOCX (`docProps/core.xml`), ODT (`meta.xml`), RTF (группа `\info`) и MOBI/AZW3/PRC
  (Palm DB → PalmDOC → MOBI → EXTH, метаданные и обложка читаются и у книг с DRM);
  определение кодировок, чтение по диапазонам без временных копий, защита от zip-бомб.
  Форматов без разбора не осталось: в сборке без CBR формат честно не предлагается, а не
  помечается «не поддерживается» на живом файле.
* **Полка**: фасетные фильтры (автор, серия, жанр, формат, статус), поиск FTS, сортировка и
  группировка, обзор по авторам/сериям/жанрам, полки (ручные и умные по тем же правилам, что и
  фильтры), карточка книги с правкой метаданных (в приложении и в самом файле).
* **OPDS 1.2**: каталоги, навигация и acquisition-фиды, поиск (OpenSearch и по загруженному фиду),
  загрузки с очередью, историей и понятной причиной отказа; шаблоны пути с подпапками.
* **Обслуживание**: оптимизация FB2 без потери данных, поиск дублей, выгрузка и импорт библиотеки
  в JSON, резервные копии базы с восстановлением и перезапуском, уборка кэша обложек по лимиту.
* **Фон и e-ink**: WorkManager-работы (синхронизация, разбор, скан, загрузка OPDS, резервная копия
  базы, уборка кэша обложек) — все уступают открытой читалке; режимы экрана через вендорские контроллеры
  (Onyx SDK рефлексией, Rockchip через `setByEinkUpdateMode`, иначе no-op); запуск внешней читалки.

**Что ещё заглушки** (полный список — `bash tools/list-stubs.sh`):

* `:core:readerlink` — привязка к сервисам FBReader (`bindService`, подписка на `ACTION_API_CALLBACK`),
  подтверждение пакетов KOReader/AlReader/Librera; проверяется вручную на устройстве с читалкой.
  Профили читалок в базе уже работают (`ReaderProfileRepositoryImpl` в `:core:data`: таблицы
  `reader_profiles` и `format_defaults`, встроенный preset удалить нельзя) — заглушкой остаётся
  сама привязка к сервису и порядок выбора читалки (`ReaderResolver`, пока без вызовов).
* `:core:eink` — вендорские режимы обновления и проверка точных FQN классов SDK; реальные режимы
  проверяются только на живых устройствах. Подсветка реализована без SDK (`SysfsFrontLightController`):
  уровень пишется долей от `max_brightness`, а если узел недоступен, приложение честно говорит «нет».
  ЗАМЕР на Bigme B6 Color (01.10.2026, Android 14, ядро 4.19.191): каталога `/sys/class/backlight`
  нет вовсе, `/sys/class/leds` приложению не читается (SELinux) — на этом устройстве строка
  подсветки не показывается, и это правильное поведение, а не дефект.
* Прочее: ручные правки прогресса чтения (`ReadingProgressRepository.setManualPercent/clear`
  возвращают `Unsupported` и пока нигде не вызываются — это будущая функция, а не сломанная),
  фильтрация журнала из настроек, нормализация названий для сортировки. Уже сделано: параллелизм
  разбора (`AppDispatchers.metadata`), фильтр по источнику (папке) в фильтрах, автофокус поля
  поиска, подсветка e-ink через sysfs, профили читалок в базе, разбор CBR во flavor `full`.
  `CoverExtractor` не нужен — обложки приходят из разбора (см. `ParseResult`).

**Известные ограничения честно:** инструментальные тесты есть (`app/src/androidTest`: запуск
приложения, обход SAF на живом провайдере, FileProvider, доставка книги в читалку, подсветка) —
прогоняются вручную через Windows-`adb` (`docs/TESTING.md`), потому что Gradle из контейнера
устройство не видит; миграции 5→6, 6→7 и 7→8 проверены тестами И на устройстве
(91 книга, `integrity_check = ok`).

**ЖДЁТ РЕШЕНИЯ АЛЕКСАНДРА** (без него не делаю): вендорский SDK Onyx для подсветки на его
устройствах. Решения по flavor-флагам и распаковщику RAR приняты 02.10.2026 и выполнены:
`junrar` подключён только во flavor `full`, а `opdsEnabled`/`allowAllFilesAccess` теперь
управляют интерфейсом и доступом к файлам (ADR-006).

## Технические особенности проекта

* **Никаких анимаций, теней и полупрозрачности** — e-ink перерисовывается сотни миллисекунд,
  а полутона «выцветают». Отклик — инверсией блока, листание — страницами, а не скроллом.
* **Ноль сетевых запросов** по умолчанию: ни аналитики, ни крашлитики. Сеть — только OPDS
  по явному действию пользователя.
* **Никогда не падать на битом файле**: ошибка разбора — это состояние книги (`FAILED`/`PARTIAL`).
* **Скан возобновляемый**: курсор обхода хранится в БД, поэтому ограничение Android 15
  (`dataSync` — 6 часов за 24) не ломает сканирование большой библиотеки.
* **Три flavor-сборки**: `full` (все файлы + CBR), `fdroid` (без несвободного `junrar`),
  `play` (только SAF и `<queries>`). Различия — через `BuildConfig`, а не `if (flavor == …)`.
* **Офлайн-первый**: библиотека, настройки и кэш живут локально; OPDS и загрузка обложек —
  единственные сетевые функции.
